# NL Event

Paste a Korean or English announcement into Description, review suggestions for Title, Start, End, and Location, then open an editable Google Calendar form or download an `.ics` file. Description, Title, Start, End, and Location remain editable after export. Nothing saves to a calendar automatically.

The application preserves SvelteKit 3 and Svelte 5, uses ReScript 12 for the functional core, and imports `@leftium/nimble.css/core` once in the root layout. Ranked alternatives appear beneath each field. Selecting one changes only that field and marks it Manual; typing, including deleting, also makes a field Manual. Each field has a muted, right-aligned **Auto** switch: on uses suggestions, off keeps the current value Manual. Typing or selecting an alternative switches it off. Turning it back on restores the latest coherent suggestion, or blank when unsupported. Description is exported exactly as entered.

Short announcements such as `lunch tomorrow` produce Title `lunch`, a noon Start tomorrow, and an inferred one-hour End. Unlabeled heading titles omit extracted dates and times; explicitly labeled titles and Manual titles keep their text. A single supported date with no clock evidence defaults to 09:00, with breakfast/lunch/dinner cues using 09:00/12:00/18:00. These times are marked inferred. Explicit all-day input and vague periods such as "tomorrow evening" retain their existing behavior. `12p` and `12a` are accepted as noon and midnight.

Parsing uses deterministic Korean/English rules, with no server, external LLM, geocoding, or NLP library defaults. Candidate evidence includes source spans, completeness, inference labels, rank, and activity/occurrence associations. Title and Location offer selectable text alternatives. Start and End split suggestions into Date and Time chips, sorted chronologically. Dates show weekday and days from today; fast tooltips expose source wording. Selecting a date chooses its associated time, or All day when none is available. Selecting a clock preserves that field's date, allowing explicit combinations outside the original source pairing. Paired times have solid borders; unpaired times have dashed borders and muted text. Both remain selectable, with a concise advisory for mixed combinations.

End shows Duration before Date and Time. Common timed shortcuts range from 15 minutes to 4 hours; all-day shortcuts offer 1, 2, 3 days and 1 week. Complete source End suggestions add durations relative to Start, capped at one day to keep long schedules manageable. The calculated duration selects its matching chip or adds a selected custom chip, including longer manually chosen ranges. Choosing a duration keeps End relative to Start; calculating one from explicit date/time choices does not change those choices.

Time-only options remain incomplete without a date in that field or the current source. Auto leaves vague periods such as "tomorrow evening" unresolved; explicitly selecting their Date chip chooses All day. Missing dates are never recovered from calendar metadata or test expectations. Fee/deadline dates remain available for explicit selection but do not become Auto event boundaries. Unused partial alternatives do not block a valid manually assembled draft. Mixed activities and retained selections from an older Description receive visible warnings.

## Development

Use Node 24 and pnpm. Run `pnpm install`, then `pnpm dev`. The dev command builds ReScript before starting Vite and watches both sources. `pnpm check`, `pnpm test`, and `pnpm build` also regenerate the typed boundary before running. Generated `.res.js` and `.gen.ts` files are ignored; edit `.res` sources instead. JavaScript checking is disabled for compiler output; ReScript checks the core and `@genType` supplies the TypeScript boundary.

- `pnpm check`: ReScript compilation and Svelte/TypeScript diagnostics.
- `pnpm test`: focused Vitest tests for state, validation, time zones, and exports.
- `pnpm test:browser`: Chromium and WebKit smoke checks against a running `pnpm dev` server. Install local browser binaries with `pnpm exec playwright install chromium webkit` if needed. Set `NL_EVENT_BASE_URL` to test another local server.
- `pnpm lint`: Prettier and ESLint.
- `pnpm build`: production build through the existing adapter-auto setup.

`src/lib/core/Parser.res` owns Korean/English extraction, date-inference policy, ranking, and associations. `TimeInput.res` interprets freeform Start/End text without rewriting it. `EventCore.res` owns draft transitions, revision checks, ownership, partial selection, validation decisions, normalization, and both serializers. `calendarAdapter.ts` provides deterministic Temporal calendar arithmetic, elapsed durations, date/zone conversion, and all possible matching instants, without choosing an ambiguous offset. `primitives.ts` supplies lexical matching, Unicode, and string operations. The Svelte page owns clipboard access, captured reference context, debounce/parse scheduling, UID/DTSTAMP generation, focus, and downloads. There is no backend or persistent draft history.

## Manual input

Start and End accept freeform Korean/English text such as `tomorrow at 7pm`, `Oct 25, 2026 at 5pm`, or `내일 오후 5시`, as well as `YYYY-MM-DD HH:mm`. The small text below each input shows its interpreted date/time in the event zone, or an actionable validation error. Both Time rows include an **All day** option independent of the Auto switches. A compact zone token beside Start opens a dialog; provenance is shown only inside it. It uses the dates covered by the current values and an inclusive End, keeping the original text, durations, and DST choices for restoration when switched off. Auto suggestions continue updating dates while All day stays on. A timed midnight End covers the preceding day; a known date without a time can become an explicit all-day event. Turning All day off requires timed values if no earlier times exist. Auto Start/End inputs and explicitly selected chips show the extracted source wording, with resolved values in the small text below. If date and clock evidence occur on separate lines, the input joins those original fragments. An inferred End keeps its suggested time because no quoted End exists. Typing replaces the source wording with your exact edit; both exports use the displayed interpretation. Relative dates use the draft's fixed reference context, and End date/time expressions resolve independently without adding the parser's default duration. Start also accepts a duration such as `30min` or `2hr`, meaning that much elapsed time from now. Capture the current minute when Start is edited and keep that anchor stable through other edits and exports; editing Start again captures a new anchor. End also accepts an explicit duration such as `4hr`, `90min`, or `1h30m`; its preview and both exports use Start plus that elapsed duration, and update when Start changes. Durations require a complete timed Start, including a DST offset choice when needed. Fractional hours are supported when they produce whole minutes; zero/negative timed durations are rejected. All-day End accepts positive whole day/week durations, counted inclusively from Start. Time-only text still needs a date; vague periods still need a clock time. Use `all day tomorrow` to explicitly choose an all-day date. Enter both Start and End as `YYYY-MM-DD` for all-day events; End includes that date. Both exports use the same normalized event and exclusive all-day end. Invalid dates, mixed formats, reversed ranges, unknown timed zones, DST gaps, and unresolved overlaps block export. For repeated local times, choose an offset independently for Start and End. Changing zone keeps wall-clock text and clears those choices. Source IANA zones take precedence over recognized city inference (St Paul/Minneapolis, MN -> America/Chicago), then browser fallback. A manual override takes precedence over all three and survives Description edits/clearing. Conflicting or unsupported source zones require confirmation. Zone edits refresh suggestions against the fixed reference instant without applying new Auto values; reset a field or edit Description to apply them.

Ordinary Description edits debounce for 250 ms; paste starts parsing immediately. Pending evidence is hidden and exports wait for the current parse. Draft identity, Description revision, and zone-context revision reject stale results. Manual edits during parsing win. Clearing Description removes evidence and Auto values while retaining Manual fields, zone override, and UID. Parse failure clears suggestions and Auto values but leaves manual completion and export available.

**Reset** immediately clears the current draft without a confirmation dialog. Native paste into Description edits the current draft. Select text in Description and choose **Use selection as Title** to copy it exactly into a Manual Title without changing the other fields. **Paste from clipboard** reads first, preserves the draft on failure or empty text, and immediately replaces a populated draft after a successful nonempty read, without a confirmation dialog. Clipboard access requires browser permission and a secure context such as HTTPS or localhost.

The first `.ics` download allocates a UID reused after edits and later downloads. Reset clears it. Imports may still duplicate events depending on the calendar application. Long Google URLs can exceed platform limits and expose the description in browser history; the file export keeps the complete description without a URL handoff.

## Scope and verification

The [product specification](specs/nl-event-spec.md) defines the broader resolver. The [fixture contract](tests/fixtures/nl-event/README.md) defines the 14 adopted source cases. Inputs, expectations, provenance, and the independent calendar oracle remain unchanged. Fixture tests inject only reference context into parsing and compare assertions afterward. The E3 calendar oracle remains separate conversion/serialization evidence; it never supplies parser dates. K1/K2 remain excerpts and K3 remains synthetic. Missing originals and E4 source coverage remain follow-ups.

Unit tests cover all 14 parser fixtures plus ownership and stale-result races, partial resolution, associated End resets, relative/week/year rules, midnight zone context, weekday contradictions, inferred elapsed durations, UID reuse/reset, strict dates, all-day bounds, time-zone overrides, Chicago DST gaps and both overlap choices, normalized Google/ICS equivalence, query encoding, text escaping, CRLF, and UTF-8-safe folding. Chromium and WebKit smoke checks exercise all 14 inputs and their preferred/blocked outcomes through the UI, field alternatives and sibling independence, partial selection/completion, pending/new-draft invalidation, real file downloads, freeform interpretation/export parity, clipboard failure/empty/replacement (with stubbed reads), absence of confirmation dialogs, ownership, UID reuse/reset, DST controls, focus, and a 390px viewport. Google URL contents are checked locally; signed-in Google prefill and actual calendar import remain unverified. Implementation verification is recorded in PR #2. Physical macOS calendar import, iPhone Safari and Android Chrome with/without the Google Calendar app require device verification. A responsive desktop browser viewport does not verify those device combinations.
